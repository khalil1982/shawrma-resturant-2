# Business Requirements Document (BRD)
## Electron Offline-First Shawarma Restaurant Management System
## Phase-Based Structure

---

## Phase 1: Analysis & UI/UX Design

### الهدف
تثبيت الرؤية الكاملة للنظام قبل أي تطوير برمجي، وحسم جميع قرارات التصميم وتجربة المستخدم.

### النطاق
- تحليل المستخدمين (Cashier / Admin)
- تحليل تدفق العمل اليومي داخل المطعم
- اعتماد قرارات UI/UX النهائية
- تصميم Wireframes للشاشات الأساسية
- توثيق قرارات التصميم داخل BRD

### قرارات معتمدة
- تصميم حديث وجذّاب بصريًا
- ألوان دافئة مع تباين واضح
- واجهة مقسّمة (أصناف / تفاصيل الطلب / ملخص)
- أيقونات فقط بدون صور
- تفاعلية بسيطة
- وضع فاتح مع قابلية Dark Mode لاحقًا
- قوائم منبثقة للإعدادات والتقارير
- تنبيهات فورية وواضحة

### المخرجات
- Wireframes معتمدة
- مرجع UI/UX رسمي
- إغلاق كامل لقرارات التصميم


---

## Phase 2: Foundation & Architecture

### الهدف
بناء الأساس التقني للتطبيق وفق مبدأ Offline-First وبنية قابلة للتوسّع.

### النطاق
- إعداد Electron Desktop Application
- هيكلة المشروع (UI / Logic / Data)
- إعداد SQLite Local Database
- نظام الصلاحيات (Admin / Cashier)
- دعم اللغة العربية والاتجاه RTL
- فصل منطق الأعمال عن الواجهة

### المخرجات
- تطبيق Electron أساسي يعمل محليًا
- قاعدة بيانات محلية
- بنية تقنية جاهزة للتطوير


---

## Phase 3: Core Operations (Sales & Shifts)

### الهدف
تشغيل المطعم فعليًا من خلال المبيعات والورديات.

### النطاق
- إدارة الورديات (صباحية / مسائية)
- لا مبيعات بدون وردية نشطة
- فتح الوردية يدويًا من Admin
- تسجيل الطلبات النقدية
- احتساب الإجمالي تلقائيًا
- ربط الطلبات بالوردية
- منع التعديل أو الحذف إلا بصلاحية Admin

### المخرجات
- شاشة مبيعات فعّالة
- نظام ورديات موثوق
- بيانات تشغيل يومي دقيقة


---

## Phase 4: Financial Control & Reports

### الهدف
ضبط العمليات المالية اليومية وتوفير رؤية مالية دقيقة.

### النطاق
- احتساب الرصيد المتوقع
- إدخال الرصيد الفعلي
- احتساب الفروقات وإلزام سبب الفرق
- Audit Log & Adjustments
- سياسة التعامل مع انقطاع الكهرباء
- تسجيل المصاريف والمشتريات
- تقارير (يومي / فترة / وردية)
- تصدير PDF / Excel

### المخرجات
- رقابة مالية كاملة
- تقارير دقيقة وقابلة للتصفية
- سجل تدقيق واضح


---

## Phase 5: Optimization & Expansion

### الهدف
تحسين النظام والاستعداد للتوسّع المستقبلي دون إعادة بناء.

### النطاق
- تحسين الأداء والاستقرار
- تحسين تجربة المستخدم
- توحيد منطق الأعمال
- إعداد Local API Layer
- التحضير لتطبيق موبايل Offline-First
- دعم المبيعات الكاملة من الموبايل

### المخرجات
- نظام مستقر ومحسّن
- جاهزية للتوسّع متعدد المنصات
