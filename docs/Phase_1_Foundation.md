# Phase 1 – Analysis & UI/UX Design

## 🎯 الهدف الرئيسي
تثبيت الرؤية الكاملة للنظام قبل أي تطوير برمجي، وحسم جميع قرارات التصميم وتجربة المستخدم لضمان سير العمل بسلاسة دون تعديلات كبيرة لاحقة.

---

## 📋 النطاق التفصيلي

### 1. تحليل المستخدمين (User Analysis)

#### 1.1 الكاشير (Cashier)
**الدور والمسؤوليات:**
- استقبال الطلبات من الزبائن
- تسجيل الطلبات في النظام بسرعة ودقة
- احتساب الإجمالي وتحصيل المبالغ
- طباعة الفواتير
- **لا يملك صلاحية** فتح أو إغلاق الوردية
- **لا يملك صلاحية** تعديل أو حذف الطلبات المسجلة
- **لا يملك صلاحية** الوصول للتقارير المالية

**الاحتياجات:**
- واجهة سريعة وسهلة الاستخدام
- وضوح الأصناف والأسعار
- سرعة إدخال الطلبات (زر واحد لكل صنف)
- رؤية فورية للإجمالي
- تنبيهات واضحة عند الأخطاء

#### 1.2 المدير (Admin)
**الدور والمسؤوليات:**
- فتح وإغلاق الورديات
- مراجعة المبيعات اليومية
- إدخال الرصيد الفعلي ومطابقته مع المتوقع
- تسجيل أسباب الفروقات المالية
- تسجيل المصاريف والمشتريات
- الوصول الكامل للتقارير
- تعديل وحذف البيانات عند الضرورة
- إدارة إعدادات النظام

**الاحتياجات:**
- لوحة تحكم شاملة
- تقارير واضحة ودقيقة
- إمكانية التصدير (PDF / Excel)
- رؤية مالية فورية
- سجل تدقيق (Audit Log)

### 2. تحليل تدفق العمل اليومي (Workflow Analysis)

#### 2.1 بداية اليوم (صباحاً)
```
1. المدير يفتح النظام
2. المدير يفتح الوردية الصباحية
3. يدخل رصيد البداية (إن وجد)
4. الكاشير يبدأ باستقبال الطلبات
```

#### 2.2 أثناء الوردية
```
1. الكاشير يسجل الطلبات
2. النظام يحسب الإجماليات تلقائياً
3. الطلبات تُربط بالوردية النشطة
4. لا يمكن التسجيل بدون وردية نشطة
```

#### 2.3 نهاية الوردية (ظهراً أو مساءً)
```
1. المدير يغلق الوردية
2. النظام يحسب الرصيد المتوقع تلقائياً
3. المدير يدخل الرصيد الفعلي
4. النظام يحسب الفرق
5. إذا كان هناك فرق → المدير يُدخل السبب (إجباري)
6. اعتماد الإغلاق
```

#### 2.4 عند فتح الوردية الثانية (مسائية)
```
1. المدير يفتح الوردية المسائية
2. يدخل رصيد البداية (من الوردية الصباحية)
3. نفس الإجراءات تتكرر
```

### 3. قرارات UI/UX المعتمدة

#### 3.1 الألوان (Color Palette)
**نظام اللون الأساسي:**
- **Primary Color:** برتقالي/ذهبي دافئ (#FF8C00 / #FFA500) - يعكس حرارة الشاورما
- **Secondary Color:** بني داكن (#8B4513 / #A0522D) - يعكس اللحم المشوي
- **Accent Color:** أخضر فاتح (#90EE90) - للنجاح والتأكيد
- **Background:** أبيض (#FFFFFF) / رمادي فاتح جداً (#F5F5F5)
- **Text Primary:** رمادي داكن (#333333)
- **Text Secondary:** رمادي متوسط (#666666)
- **Danger:** أحمر (#DC3545) - للأخطاء والتحذيرات
- **Info:** أزرق فاتح (#17A2B8) - للمعلومات

**التباين:**
- تباين واضح بين الخلفية والنصوص (WCAG AA Compliant)
- أزرار بارزة بألوان دافئة
- حدود واضحة للتمييز بين الأقسام

#### 3.2 التخطيط (Layout)
**شاشة المبيعات الرئيسية:**
```
+---------------------------------------------------+
|  [Logo]  مطعم الشاورما      [الإعدادات] [التقارير]  |
+---------------------------------------------------+
|                                                    |
|  [قائمة الأصناف]    |    [تفاصيل الطلب الحالي]     |
|                     |                              |
|  - شاورما دجاج      |   x2  شاورما دجاج      10.00  |
|  - شاورما لحم       |   x1  كولا               1.50  |
|  - مشروبات          |                              |
|  - إضافات           |   ----------------------     |
|                     |   الإجمالي:           11.50  |
|                     |                              |
|                     |   [تأكيد الطلب]              |
+---------------------------------------------------+
```

**توزيع الشاشة:**
- **يسار (40%):** قائمة الأصناف مع الأيقونات والأسعار
- **يمين (60%):** تفاصيل الطلب الحالي مع الإجمالي
- **أعلى:** شريط التنقل والإعدادات
- **أسفل:** أزرار الإجراءات الرئيسية

#### 3.3 الأيقونات (Icons)
**استخدام أيقونات بدون صور:**
- Font Awesome أو Material Icons
- أيقونات واضحة لكل صنف:
  - 🍗 شاورما دجاج
  - 🥩 شاورما لحم
  - 🥤 مشروبات
  - 🍟 إضافات
  - 💰 المبيعات
  - 📊 التقارير
  - ⚙️ الإعدادات
  - 🔒 تسجيل الخروج

#### 3.4 التفاعلية (Interactions)
**التفاعلات الأساسية:**
- **Hover Effect:** تغيير خفيف باللون عند المرور بالماوس
- **Click Feedback:** تأثير Ripple أو تغيير لون فوري
- **Smooth Transitions:** انتقالات سلسة (200-300ms)
- **Loading States:** مؤشرات تحميل واضحة
- **Disabled States:** عرض واضح للأزرار المعطلة

**التنبيهات:**
- **Success:** إطار أخضر مع أيقونة ✓
- **Error:** إطار أحمر مع أيقونة ✕
- **Warning:** إطار برتقالي مع أيقونة ⚠
- **Info:** إطار أزرق مع أيقونة ℹ

#### 3.5 دعم RTL واللغة العربية
- **اتجاه النصوص:** من اليمين لليسار (RTL)
- **الخطوط:** Tajawal, Cairo, أو Noto Sans Arabic
- **حجم الخط:**
  - عناوين: 24-28px
  - نصوص عادية: 16-18px
  - نصوص صغيرة: 14px
- **توزيع العناصر:** عكس التوزيع الإنجليزي
- **الأيقونات:** محاذاة مع اتجاه النص

#### 3.6 الوضع الليلي (Dark Mode)
**مؤجل للمراحل اللاحقة:**
- سيتم إضافة Dark Mode في Phase 5
- البنية ستكون جاهزة من البداية
- استخدام CSS Variables لسهولة التبديل

### 5. القرارات التقنية للتصميم

#### 5.1 إطار العمل للواجهة
**الخيارات:**
- **React + TailwindCSS** (موصى به)
  - سرعة التطوير
  - مكتبة مكونات جاهزة
  - دعم RTL ممتاز
- **Vue.js + Vuetify**
  - مكونات Material Design
  - سهل التعلم
- **Vanilla JavaScript + Custom CSS**
  - أداء أفضل
  - تحكم كامل

**القرار المعتمد:** React + TailwindCSS + Shadcn/UI

#### 5.2 مكتبات UI
- **Shadcn/UI:** مكونات جاهزة قابلة للتخصيص
- **React Hook Form:** إدارة النماذج
- **Zod:** التحقق من البيانات
- **date-fns:** معالجة التواريخ
- **react-hot-toast:** التنبيهات

#### 5.3 الطباعة
- **electron-pos-printer:** طباعة الفواتير
- دعم الطابعات الحرارية (Thermal Printers)
- تنسيق فاتورة واضح بالعربية

### 6. متطلبات إمكانية الوصول (Accessibility)

#### 6.1 معايير WCAG
- **Level AA Compliance:**
  - تباين الألوان: نسبة 4.5:1 على الأقل
  - حجم الخط: 16px على الأقل
  - مناطق النقر: 44x44px على الأقل
  - دعم لوحة المفاتيح الكامل

#### 6.2 التنقل بلوحة المفاتيح
- **Tab:** الانتقال بين الحقول
- **Enter:** تأكيد الإجراء
- **Esc:** إلغاء/إغلاق
- **Arrow Keys:** التنقل بين الأصناف
- **Space:** تحديد الصنف

#### 6.3 Screen Readers
- استخدام ARIA Labels
- عناوين واضحة للأقسام
- وصف للأيقونات

### 7. حالات الاستخدام (Use Cases)

#### UC-1: تسجيل طلب جديد
```
Actor: Cashier
Precondition: وردية نشطة موجودة
Flow:
  1. الكاشير يفتح شاشة المبيعات
  2. يختار الأصناف من القائمة
  3. النظام يحسب الإجمالي تلقائياً
  4. يضغط "تأكيد الطلب"
  5. النظام يسجل الطلب ويربطه بالوردية
  6. يطبع الفاتورة
Postcondition: الطلب مسجل والفاتورة مطبوعة
```

#### UC-2: فتح وردية جديدة
```
Actor: Admin
Precondition: لا توجد وردية نشطة
Flow:
  1. المدير يفتح شاشة الورديات
  2. يضغط "فتح وردية جديدة"
  3. يختار نوع الوردية (صباحية/مسائية)
  4. يدخل رصيد البداية (اختياري)
  5. يضغط "تأكيد"
  6. النظام يفتح الوردية
Postcondition: وردية نشطة جاهزة للمبيعات
```

#### UC-3: إغلاق وردية
```
Actor: Admin
Precondition: وردية نشطة موجودة
Flow:
  1. المدير يضغط "إغلاق الوردية"
  2. النظام يعرض الرصيد المتوقع
  3. المدير يدخل الرصيد الفعلي
  4. النظام يحسب الفرق
  5. إذا كان هناك فرق:
     - المدير يدخل السبب (إجباري)
  6. يضغط "اعتماد الإغلاق"
  7. النظام يغلق الوردية ويسجل البيانات
Postcondition: الوردية مغلقة والبيانات محفوظة
```
