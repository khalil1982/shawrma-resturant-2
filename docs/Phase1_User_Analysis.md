# Phase 1: تحليل المستخدمين والتدفقات
## Shawarma Restaurant Management System

---

## 1. تحليل المستخدمين (User Analysis)

### 1.1 المستخدم الأول: الكاشير (Cashier)

**الدور الوظيفي:**
- تسجيل المبيعات والطلبات
- التعامل المباشر مع العملاء
- معالجة الدفعات النقدية

**الاحتياجات:**
- واجهة سريعة وبسيطة
- القدرة على إدخال الطلبات بسرعة
- رؤية واضحة لإجمالي الطلب
- تأكيدات فورية للعمليات

**نقاط الألم (Pain Points):**
- ضيق الوقت في أوقات الذروة
- الحاجة لدقة عالية في الحسابات
- صعوبة التعامل مع الأنظمة المعقدة

**القيود:**
- لا يمكنه فتح أو إغلاق الورديات
- لا يمكنه تعديل أو حذف الطلبات
- لا يمكنه الوصول للتقارير المالية

---

### 1.2 المستخدم الثاني: المدير (Admin/Manager)

**الدور الوظيفي:**
- إدارة الورديات
- مراقبة العمليات المالية
- اتخاذ القرارات الإدارية
- مراجعة التقارير

**الاحتياجات:**
- صلاحيات كاملة على النظام
- تقارير مالية دقيقة وشاملة
- القدرة على تتبع الفروقات المالية
- رؤية واضحة لأداء المطعم

**نقاط الألم:**
- الحاجة للرقابة المالية الدقيقة
- صعوبة تتبع الفروقات المالية
- الحاجة لتحليل الأداء بسرعة

**الصلاحيات:**
- فتح وإغلاق الورديات
- تعديل وحذف الطلبات (مع تسجيل audit)
- إضافة وتعديل المستخدمين
- الوصول لجميع التقارير
- إدارة المصاريف والمشتريات

---

## 2. تحليل تدفق العمل اليومي (Daily Workflow)

### 2.1 سيناريو اليوم العملي الكامل

#### الصباح (الوردية الصباحية)

**الخطوة 1: فتح الوردية**
- المدير يسجل دخوله للنظام
- يفتح وردية جديدة (صباحية)
- يدخل رصيد الافتتاح النقدي
- النظام يسجل وقت الفتح تلقائياً

**الخطوة 2: تسجيل المبيعات**
- الكاشير يسجل دخوله
- يبدأ باستقبال الطلبات
- لكل طلب:
  1. اختيار نوع الطلب (محلي/سفري)
  2. اختيار الأصناف من القائمة
  3. النظام يحسب الإجمالي تلقائياً
  4. تأكيد الطلب
  5. الطلب يُربط تلقائياً بالوردية النشطة

**الخطوة 3: نهاية الوردية**
- المدير يراجع المبيعات
- يحسب النقد الفعلي
- يدخل الرصيد الفعلي في النظام
- النظام يحسب الفرق تلقائياً
- إذا وجد فرق، يجب إدخال السبب
- إغلاق الوردية

#### المساء (الوردية المسائية)

**نفس التدفق مع:**
- رصيد الافتتاح قد يكون مختلفاً
- وردية مسائية جديدة
- مبيعات منفصلة تماماً عن الصباح

---

### 2.2 سيناريوهات خاصة

#### السيناريو 1: انقطاع الكهرباء

**المشكلة:**
- انقطاع مفاجئ للكهرباء أثناء تسجيل طلب

**الحل:**
- النظام offline-first
- جميع البيانات محلية
- عند عودة الكهرباء، البيانات محفوظة
- آخر طلب مُدخل قبل الانقطاع موجود
- الوردية لا تزال نشطة

#### السيناريو 2: فرق مالي

**المشكلة:**
- الرصيد الفعلي لا يطابق المتوقع

**الحل:**
1. النظام يعرض الفرق بوضوح
2. إلزام المدير بإدخال سبب الفرق
3. تسجيل الفرق في audit log
4. إمكانية مراجعة الفروقات لاحقاً

#### السيناريو 3: خطأ في طلب

**المشكلة:**
- تم تسجيل طلب خاطئ

**الحل للكاشير:**
- لا يمكنه التعديل أو الحذف
- يطلب من المدير التدخل

**الحل للمدير:**
- يمكنه تعديل الطلب
- يمكنه حذف الطلب
- النظام يسجل كل تعديل في audit log
- يُطلب منه سبب التعديل/الحذف

## 3. متطلبات تجربة المستخدم الأساسية

### 3.1 السرعة
- الشاشات يجب أن تستجيب فوراً
- لا انتظار للتحميل (offline-first)
- أقل عدد من النقرات لإتمام العملية

### 3.2 الوضوح
- المعلومات المهمة بارزة ومرئية
- الألوان واضحة ومتباينة
- النصوص كبيرة وقابلة للقراءة
- الأزرار واضحة ومحددة

### 3.3 الأمان
- تسجيل دخول إلزامي
- صلاحيات واضحة لكل مستخدم
- تسجيل كل عملية حساسة
- حماية من الحذف أو التعديل غير المصرح

### 3.4 الدعم العربي
- جميع النصوص بالعربية
- الاتجاه من اليمين لليسار (RTL)
- تنسيق التواريخ والأرقام بالعربي

---

## 4. الشاشات الأساسية المطلوبة

### 4.1 شاشة تسجيل الدخول
- اسم المستخدم
- كلمة المرور
- زر تسجيل الدخول
- رسالة خطأ واضحة

### 4.2 شاشة إدارة الوردية (Admin فقط)
- حالة الوردية الحالية
- فتح وردية جديدة
- إغلاق الوردية النشطة
- ملخص الوردية

### 4.3 شاشة المبيعات (POS)
- قائمة الأصناف (يسار)
- تفاصيل الطلب الحالي (وسط)
- ملخص وإجمالي (يمين)
- أزرار التحكم (تأكيد، إلغاء)

### 4.4 شاشة التقارير (Admin فقط)
- تقرير يومي
- تقرير فترة مخصصة
- تقرير وردية محددة
- تصدير PDF/Excel

### 4.5 شاشة المصاريف (Admin فقط)
- إضافة مصروف جديد
- قائمة المصاريف
- ربط المصروف بالوردية أو اليوم

## 5. القرارات المعتمدة

✅ نظام offline-first كامل
✅ دعم RTL والعربية بالكامل
✅ نظام صلاحيات صارم (Admin/Cashier)

✅ ربط إلزامي للطلبات بالوردية
✅ لا مبيعات بدون وردية نشطة
✅ فروقات مالية تتطلب سبباً إلزامياً
